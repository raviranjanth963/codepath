Think of Git as a tool that tracks your project's history and GitHub as a place where you can store and share that history online.

Introduction to Git and GitHub

What is Version Control?

Version control is a system that helps developers track changes made to files over time.

Imagine you are creating a website. You make changes to your HTML, CSS and JavaScript files every day.

After some time:

  • You accidentally delete some important code.
  • Your new design does not work.
  • You want to return to the previous version.
  • You want to know who changed a particular part of the code.

Version control helps you manage these situations.

Main benefits:

  1. Tracks changes in your code.
  2. Allows you to return to previous versions.
  3. Helps multiple developers work together.
  4. Maintains a history of project changes.
  5. Makes it easier to recover lost or incorrect code.

What is Git?

Git is a free and open-source distributed version control system.

It allows developers to track changes, save project versions, create branches, and combine code changes.

Example:

Suppose you create a website named CodePath.

  • Day 1: You create the homepage.
  • Day 2: You add a login page.
  • Day 3: You add a registration page.
  • Day 4: You change the website design.

Git can record these changes so that you can see the project's history and return to an earlier version when necessary.

What is GitHub?

GitHub is an online platform for hosting Git repositories.

Developers use GitHub to:

  • Upload and store projects.
  • Share code with others.
  • Work with teams.
  • Review code changes.
  • Report bugs.
  • Manage project development.
  • Contribute to open-source projects.

You can install Git on Windows, macOS (MacBook), and Linux.

Where to download Git?

Official Git website

Module 3: Set Up Git for the First Time

After installing Git, you need to configure your identity.

Git uses your name and email address to identify who created each commit.

1. Configure your username

Open Git Bash on Windows or Terminal on Mac.

Type:


git config --global user.name "Your Name"

Example:

Type:


git config --global user.name "Raviranjan"

2. Configure your email


git config --global user.email "your-email@example.com"

Use the email address associated with your GitHub account if you want your commits linked to that account.

3. Check Git configuration


git config --list

This displays your Git configuration.

4. Set the default branch name


git config --global init.defaultBranch main

This makes main the default initial branch when you create new repositories.

What is a Repository?

A repository (also called a repo) is a place where your project's files and their version history are stored.

A repository can contain:

  • HTML files
  • CSS files
  • JavaScript files
  • Images
  • Python files
  • Documentation
  • Other project resources

There are two common types:

  1. Local repository: Stored on your computer.
  2. Remote repository: Stored on an online platform such as GitHub.

Module 4: Understanding the Git Workflow

Before learning commands, understand how Git saves changes.

Git has three important local areas:

1. Working Directory

This is where you create and edit your project files.

Example;

  • index.html
  • style.css
  • script.js

2. Staging Area

This is where you select the changes you want to include in your next commit.

3. Local Repository

This is where Git stores your committed project history.

There is also a fourth destination:

4. Remote Repository

This is an online repository, such as GitHub, where you can upload your commits and collaborate with other developers.

Remember these three main commands:

  • git add – Select changes.
  • git commit – Save changes in Git history.
  • git push – Upload commits to GitHub.

Git Commands – Basic Commands

1. What is a Git Command?

A Git command is an instruction entered into a terminal to perform an operation on a Git repository.

2. Check Git version


git --version

Displays the installed Git version.

3. Clear the terminal


clear

Clears the terminal screen. This is a shell command, not a Git command.

4. List files and folders


ls

Displays files and folders in the current directory.

To display hidden files:


ls -a

Git repositories contain a hidden .git folder, which stores repository data.

5. Check Git configuration


git config --list

Displays configured Git settings.

6. Check Git help


git help

Displays general Git help.

To get help for a particular command:


git help commit

Module 6: Git Repository – Init and Clone

1. What is git init?

git init is used to create a new Git repository inside an existing project folder.

In simple words, it tells Git to start tracking a project's history.

Example:

Suppose you have a folder called CodePath.

Step 1: Open the folder in your terminal.


cd CodePath

Step 2: Initialize Git.


git init

Example output:


Initialized empty Git repository

Git creates a hidden .git directory.

Your project is now a Git repository.

2. What is git clone?

git clone is used to download an existing remote repository to your computer.

It creates a local copy of the repository, including its Git history.


git clone https://github.com/username/project-name.git

Replace the URL with the actual GitHub repository URL.

After cloning, enter the project folder:


cd project-name

When should you use it?

  • When downloading your own GitHub project to another computer.
  • When working on another developer's project.
  • When contributing to open-source projects.

3. Difference between git init and git clone

git init git clone
Creates a new local repository Copies an existing repository
Starts tracking a folder Downloads project files and history
Used for a new project Used for an existing project
Does not automatically connect to GitHub Normally configures the original remote

Git Status, Add and Commit

hese three commands are among the most important commands in Git.

1. What is git status?

git status displays the current state of your working directory and staging area.

It tells you:

  • Which files are new.
  • Which files have been modified.
  • Which files are staged.
  • Which branch you are currently using.
  • Whether your working directory is clean.

Command


git status

Four important file states

Untracked

A new file that Git is not currently tracking.


Untracked files:
    index.html

Modified

A file that Git already knows about but that has been changed.

Staged

A file whose changes have been selected for the next commit.

Unmodified

tracked file that has not changed since its last commit.

2. What is git add?

git add moves changes into the staging area.

It tells Git which changes you want to include in your next commit.

Add one file:


git add index.html

Add multiple files:


git add index.html style.css

Add all changes in the current directory:


git add .

Another commonly used option:


git add -A

This stages additions, modifications and deletions across the working tree.

3. What is git commit?

A commit is a saved snapshot of staged changes in the Git repository.

It records what changed and includes information such as the author, date and commit message.

Command:


git commit -m "Initial commit"

Here

  • git commit

    creates a commit.

  • -m

    allows you to provide a message.

  • "Initial commit"

    describes the changes.

Example:


git add .
git commit -m "Created CodePath homepage"

4. Why are commit messages important?

Commit messages help developers understand the history of a project.

Good examples:


Added login page
Fixed navigation bar
Updated homepage design
Added registration form
Fixed mobile responsive layout

Avoid unclear messages such as:


hello
abc
changes
new

5. Difference between git add and git commit

git add git commit
Selects changes Records selected changes
Sends changes to staging area Saves them in local repository
Does not create a commit Creates a commit

Push Command – Upload Code to GitHub

1. What is git push?

git push uploads your local commits to a remote repository such as GitHub.

It allows other people to access the latest committed version of your project.

Command:


git push origin main

Meaning:

  • git push> – Upload commits.
  • origin – The conventional name for a remote repository.
  • main – The branch you want to push.

2. What is origin?

origin is a commonly used nickname for the remote repository from which your local repository was cloned, or the remote you configured yourself.

It is not a special GitHub account or a separate repository.

3. What is main?

main is commonly used as the default branch name.

It is the branch that many projects use for their primary development history.

4. What is git push -u origin main?


git push -u origin main

The -u option sets the upstream tracking relationship between your local branch and the remote branch.

After configuring it, you can often use:


git push

nstead of typing the full command every time.

5. Complete example


git status
git add .
git commit -m "Added homepage"
git push -u origin main

Your committed changes are now uploaded to GitHub.
