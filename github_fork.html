Forking in GitHub

1. What is a Fork?

A fork is your own GitHub copy of another user's repository.

It allows you to make changes without directly modifying the original repository.

The original repository is often called the upstream repository.

Your fork is a separate repository under your GitHub account.

2. Why do we use forks?

  • To contribute to open-source projects.
  • To experiment with another developer's code.
  • To make modifications independently.
  • To propose changes to the original project.
  • To maintain your own version of a project.

3. How to fork a repository

Step 1: Open another developer's GitHub repository.

Step 2: Click the Fork button.

Step 3: Select your GitHub account as the owner.

Step 4: Enter a repository name if you want to change it.

Step 5: Click Create fork.

GitHub creates a copy of the repository under your account.

4. How to clone your fork

Copy the URL of your fork and run:


git clone https://github.com/your-username/project-name.git

Enter the folder:


cd project-name

5. What is upstream?

upstream is a conventional nickname for the original repository from which you forked.

You can connect the original repository using:


git remote add upstream https://github.com/original-owner/project-name.git

Check your remotes:


git remote -v

You should see your fork as origin and the original project as upstream.

6. How to update your fork

Fetch changes from the original repository:


git fetch upstream

Switch to your main branch:


git switch main

git switch main


git merge upstream/main

Upload the updated branch to your fork:


git push origin main

7. How to contribute to the original project

  1. Fork the original repository.
  2. Clone your fork.
  3. Create a feature branch.
  4. Make your changes.
  5. Commit your changes.
  6. Push the branch to your fork.
  7. Create a Pull Request from your fork to the original repository.
  8. Respond to review feedback.
  9. Wait for the project maintainers to merge your contribution.

8. Fork vs Clone

fork Clone
Creates a separate GitHub repository under your account Creates a local copy on your computer
Performed on GitHub Performed using Git
Useful for contributing to other projects Useful for working locally
Original repository remains separate Local copy is connected to a remote repository


Important Git Commands – Remote Repositories

Remote repositories allow developers to connect their local projects with online repositories.

1. What is git remote?

git remote manages connections to remote repositories.

Check remote repositories:


git remote

Display remote names and URLs:


git remote -v

2. What is git remote add?

This command connects your local repository to a remote repository.


git remote add origin https://github.com/username/project-name.git

Here:

  • remote add – Adds a remote connection.
  • origin – Remote nickname.
  • URL – Address of the GitHub repository.

3. What is git remote remove?

Removes a remote connection from your local repository.


git remote remove origin

It does not delete the actual GitHub repository.

4. What is git remote set-url?

Changes the URL of an existing remote.


git remote set-url origin https://github.com/username/new-project.git

5. What is git push -u?


git push -u origin main

Uploads the branch and sets its upstream tracking relationship.

6. What is git fetch origin?


git fetch origin

Downloads new information from the remote repository without automatically merging it into your current branch.

7. What is git pull origin main?


git pull origin main

Fetches and integrates changes from the remote main branch into your current branch.



Git Stash

1. What is git stash?

git stash temporarily stores changes that you have not committed yet.

Imagine you are working on the CodePath login page.

Suddenly, your teammate asks you to fix an urgent bug on another branch.

You are not ready to commit your login page changes.

Instead of losing those changes, you can use Git stash.

2. How to stash changes


git stash

This saves supported tracked-file changes and returns your working directory to a clean state.

3. Save a stash with a message


git stash push -m "Login page work"

4. View all stashes


git stash list

Example:


stash@{0}: On main: Login page work
stash@{1}: On main: Updated homepage

5. Apply the latest stash


git stash apply

Restores the latest stash but keeps it in the stash list.

6. Pop the latest stash


git stash pop

Applies the latest stash and removes it from the stash list if the application succeeds.


git stash drop

Deletes the latest stash.

To delete all stashes:


git stash clear

Be careful: deleting stashes can remove your only saved copy of uncommitted work.



Git Rebase

1. What is git rebase?

Rebase is a Git operation that moves or reapplies commits from one branch onto another base commit.

It is used to maintain a cleaner and more linear project history.

Example:

You have two branches:

  • Main
  • login-page

While you are working on the login page, another developer adds new commits to main.

You can rebase your feature branch on top of the updated main branch.

2. How to use git rebase

First, switch to your feature branch:


git switch login-page

Then update your knowledge of the remote repository:


git fetch origin

Rebase your branch:


git rebase origin/main

Git reapplies your feature branch commits on top of the latest origin/main.

3. What if a rebase conflict happens?

  1. Open the conflicted file.
  2. Resolve the conflict.
  3. Stage the resolved file.
    4. 
git add index.html
  4. Continue the rebase.

git rebase --continue

To cancel the rebase and return to the original state:


git rebase --abort

Important

Avoid rebasing commits that other developers are already using unless your team has agreed on that workflow. Rebasing changes commit history.

4. Difference between merge and rebase

Mergo Rebase
Combines branch histories Reapplies commits onto a new base
Can create a merge commit Usually creates a linear history
Preserves the original branch history structure Creates new commit IDs for reapplied commits
Useful for integrating branches seful for organizing feature-branch history


More Important Git Commands

1. git show

Displays information about a particular commit or Git object.


git show

To view a specific commit:


git show commit-hash

2. git restore

Restores files in the working directory or staging area.


git restore style.css

3. git rm

Removes a tracked file from your working directory and staging area.


git rm old-file.html

4. git mv

Renames or moves a tracked file.


git mv old-name.html new-name.html

5. git tag

A tag is used to mark a specific point in your project's history.

For example, developers use tags to mark software releases.

Create a tag:


git tag v1.0

List tags:


git tag

Push a tag to GitHub:


git push origin v1.0

Push all tags:


git push origin --tags

6. git cherry-pick

Applies the changes introduced by a specific commit to your current branch.


    git cherry-pick commit-hash

This is useful when you need one particular commit without merging an entire branch.

7. git blame

Shows which commit last changed each line of a file.


git blame index.html

It helps developers investigate when and by whom a particular line was changed.

8. git reflog

Displays the history of changes to references such as HEAD.


git reflog

It can help recover commits after mistakes such as resetting a branch.

9. git clean

Removes untracked files from the working directory.

Preview what would be removed:


git clean -n

Remove untracked files:


git clean -f

Be careful: this can permanently remove untracked files.



Git Ignore (.gitignore)

1. What is .gitignore?

.gitignore is a special file that tells Git which untracked files or directories it should ignore.

For example, a project may contain:

  • Temporary files.
  • Build folders.
  • Log files
  • Dependency folders.
  • Local environment settings.

These files may not need to be uploaded to GitHub.

2. How to create a .gitignore file

Create a file in your project folder named:


.gitignore

Example content:


# Dependency folders
node_modules/

# Environment files
.env

# Log files
*.log

# Python cache
__pycache__/

# Build folder
dist/

# Operating system files
.DS_Store
Thumbs.db

3. Why should we use .gitignore?

  1. Keeps the repository clean.
  2. Prevents unnecessary files from being tracked.
  3. Avoids uploading local configuration files.
  4. Makes collaboration easier.
  5. Reduces unnecessary repository size.

Security warning

Never upload passwords, API keys, private tokens or other secrets to GitHub. Adding a file to .gitignore does not remove it from Git if it was already committed. If a secret was exposed, revoke or rotate it immediately and remove it from the repository history when necessary.



README.md

1. What is README.md?

A README file explains what a project is about and how people can use it.

It is commonly written in Markdown format.

GitHub automatically displays a repository's README on its main page when the file is in the appropriate location.

2. What should a README contain?

A good README may include:

  • Project name.
  • Project description.
  • Features.
  • Technologies used.
  • Installation instructions.
  • How to run the project.
  • Screenshots.
  • Contribution instructions.
  • License information.

GitHub Collaboration

1. What is collaboration?

Collaboration means multiple developers working together on the same project.

GitHub provides tools to make this possible.

For example, imagine three developers are building CodePath.

  • Developer A works on the homepage.
  • Developer B works on the login page.
  • Developer C works on the registration page.

Each developer can create a separate branch, commit their work and open a Pull Request.

The team can review and merge the changes.

2. What is a GitHub Issue?

An Issue is used to report bugs, suggest features, ask questions or track tasks in a repository.

Example:


Title: Login button is not working

Description:
The login button does not respond
when users click it.

Task:
Check the JavaScript event listener.

3. What is a GitHub Discussion?

GitHub Discussions is a feature for conversations within a repository or organization.

It can be used for:

  • Questions and answers.
  • Ideas.
  • Announcements.
  • Community conversations.

4. What is a GitHub Organization?

An Organization is a shared GitHub account for managing repositories, teams and permissions across a company or group.

5. What is a Code Review?

Code review is the process of checking another developer's code before accepting it.

Reviewers may:

  • Find bugs.
  • Suggest improvements.
  • Check code quality.
  • Recommend better approaches.
  • Approve changes.


Git Authentication – Connecting Your Computer to GitHub

1. What is authentication?

Authentication verifies your identity when you access a service.

When you push code to a private GitHub repository, GitHub needs to verify that you have permission to upload the changes.

Two commonly used methods are HTTPS and SSH.

2. HTTPS authentication

A typical remote URL looks like:


https://github.com/username/project-name.git

Git can use a credential manager or browser-based authentication to securely authenticate you.

For command-line Git over HTTPS, your normal GitHub account password is not accepted as a Git password. Follow GitHub's supported authentication process, such as browser authentication or a personal access token where appropriate.

3. SSH authentication

SSH allows you to connect to GitHub using an SSH key pair.

The two parts are:

  • Public key: Added to your GitHub account.
  • Private key: Kept securely on your computer.

Generate an SSH key:


ssh-keygen -t ed25519 -C "your-email@example.com"

Start the SSH agent and add your key using the operating system's supported instructions.

Test the connection:


ssh -T git@github.com

Once SSH is configured, an SSH remote URL looks like:


git@github.com:username/project-name.git

Important: Never share your private SSH key with anyone.



GitHub Pages – Host Your Website for Free

1. What is GitHub Pages?

GitHub Pages is a GitHub service that can publish static websites directly from a repository.

You can use it to publish HTML, CSS and JavaScript websites.

For example, you can publish your CodePath learning website.

2. How to publish a website using GitHub Pages

Step 1: Create a GitHub repository.

Step 2: Upload your website files.

For example:


CodePath/
│
├── index.html
├── style.css
├── script.js
└── images/

Step 3: Open your repository on GitHub.

Step 4: Go to Settings.

Step 5: Select Pages.

Step 6: Under Build and deployment, select the appropriate deployment source, commonly Deploy from a branch.

Step 7: Select your branch, usually main.

Step 8: Select the folder containing your website files, often / (root).

Step 9: Save your settings.

Step 10: Wait for GitHub Pages to publish your website.

Your website will have a URL similar to:


https://username.github.io/repository-name/

The actual URL depends on your GitHub username and repository configuration.

Note: GitHub Pages is intended for static websites. It does not directly run server-side Python or PHP applications.



GitHub Actions – Introduction to Automation

1. What is GitHub Actions?

GitHub Actions is a platform that automates workflows in your GitHub repository.

For example, whenever a developer pushes code, GitHub Actions can automatically:

  • Run tests.
  • Check code quality.
  • Build a website.
  • Deploy an application.
  • Run scheduled workflows.

2. What is a workflow?

A workflow is an automated process defined in a YAML file.

Example file:


.github/workflows/hello.yml

Example content:


name: CodePath Workflow

on:
  push:
    branches: [main]

jobs:
  welcome:
    runs-on: ubuntu-latest

    steps:
      - name: Welcome
        run: echo "Welcome to CodePath!"

This example runs a simple command when code is pushed to the main branch.



GitHub Desktop – An Alternative to Terminal Commands

1. What is GitHub Desktop?

GitHub Desktop is a graphical application that allows you to use Git without typing every command in a terminal.

It helps beginners manage repositories visually.

You can:

  • Create repositories.
  • Clone repositories.
  • View changed files.
  • Stage changes.
  • Write commit messages.
  • Push and pull changes.
  • Create branches.
  • Publish repositories to GitHub.
Download: GitHub Desktop Official website.

2. Git vs GitHub Desktop

Git GitHub Desktop
Command-line version control tool Graphical Git application
Uses terminal commands Uses buttons and menus
Works with many remote hosting services Designed to work closely with GitHub
Suitable for command-line workflows Beginner-friendly visual workflow

Remember: GitHub Desktop does not replace Git. It provides a graphical way to perform many Git operations.
