GitHub – Getting Started

1. What is a GitHub account?

A GitHub account gives you access to GitHub's online development platform.

You can create repositories, upload projects, follow developers, collaborate with teams and contribute to public projects.

2. How to create a GitHub account

Step 1: Visit GitHub official website.

Step 2: Click Sign up.

Step 3: Enter your email address.

Step 4: Create a secure password.

Step 5: Choose a username.

Step 6: Complete the verification process.

Step 7: Follow the remaining instructions to finish creating your account.

You can now sign in to GitHub.

. How to create a new repository on GitHub

A repository stores your project's files and version history.

Step 1: Sign in to GitHub.

Step 2: Click the + icon in the top-right corner.

Step 3: Select New repository.

Step 4: Enter your repository name.

Example:


CodePath

Step 5: Add a description.

Example


A beginner-friendly website for learning programming.

Step 6: Choose repository visibility.

  • Public – Anyone can view the repository.
  • Private – Only authorized people can access it.

Step 7: Optionally select Add a README file.

Step 8: Click Create repository.

Your GitHub repository is now created.

4. How to copy a GitHub repository URL

Open your repository.

Click the green Code button.

Select HTTPS and copy the displayed URL.

Example:


https://github.com/username/CodePath.git

You can use this URL to clone the repository or connect a local project to it.

5. How to connect a local repository to GitHub

If you already have a local project, follow these steps.


git init

Initialize the repository.


git add .

Stage all files.


git commit -m "Initial commit"

Create the first commit.

Add your GitHub repository as a remote:


git remote add origin https://github.com/username/CodePath.git

Rename the current branch to main if necessary:


git branch -M main

Upload the project:


git push -u origin main

Important: If your GitHub repository already contains a README or other commits, its history may need to be integrated before pushing. For beginners, creating an empty GitHub repository is often the simplest way to start with an existing local project.

Git Branches

1. What is a branch in Git?

A branch is a separate line of development in a Git repository.

Branches allow developers to work on new features or fix bugs without directly changing the main branch.

magine you are developing the CodePath website.

Your main branch contains the working website. Now you want to create a login page.

Instead of changing the main branch directly, you can create a new branch called login-page.

Example:


main
  |
  |---- login-page
  |
  |---- registration-page
  |
  |---- homepage-design

Each branch can contain its own commits.

After completing your work, you can merge the branch into the main branch.

2. What is git branch?

This command displays the branches in your local repository.


git branch

Example output:


* main
  login-page
  registration-page

The * symbol identifies your currently selected branch.

3. How to create a new branch


git branch login-page

This creates a new branch named login-page.

It does not automatically switch you to that branch.

4. How to create and switch to a new branch

Using the modern command:


git switch -c login-page

Alternative command:


git checkout -b login-page

Both commands create the branch and switch to it.

5. How to switch between branches


git switch main

This switches to the main branch.

You can also use:


git checkout main

6. How to delete a branch


git branch -d login-page

This deletes the local branch if Git considers it safely merged.

To force-delete an unmerged local branch:


git branch -D login-page

Be careful

The -D option can delete a branch that contains work you have not merged.

7. How to rename a branch


git branch -m new-branch-name

This renames the current branch.

8. How to upload a new branch to GitHub


git push -u origin login-page

This uploads the branch to GitHub and establishes upstream tracking.

9. How to see all branches

Local branches:


git branch

Remote-tracking branches:


git branch -r

Local and remote-tracking branches:


git branch -a

10. Why do developers use branches?

  • To develop new features.
  • To fix bugs.
  • To experiment with code.
  • To work with other developers.
  • To keep the main branch stable.
  • To review code before merging.


Module 11: Merging Code

1. What is merging?

Merging is the process of combining changes from one branch into another branch.

For example:

You have two branches:

  • main

  • login-page

You have completed the login page in the login-page branch.

Now you want to combine the login page code with the main project.

This process is called merging.

2. How to merge two branches

Suppose you are working on login-page and have finished your work.

Step 1: Save your changes.


git git add .
git commit -m "Completed login page"

Step 2: Switch to the main branch.


git switch main

Step 3: Merge the login-page branch.


git merge login-page

Now Git attempts to combine the changes into the main branch.

Step 4: Upload the updated main branch.

3. What is git diff?

git diff is used to compare changes in your files.

It shows what has been added, removed or modified.

Command:


git diff

It compares unstaged working-directory changes with the staging area.

Other useful commands:


git diff --staged

Shows changes that have been staged but not committed.


git diff main login-page

Compares the tips of the two specified branches.

4. What is git merge?


git merge branch-name

Combines the specified branch into your current branch.

Remember that you should first switch to the branch into which you want to merge.

5. What is git log?

git log displays the history of commits.


git log

For a shorter history:


git log --oneline

To display a graphical branch history:


git log --oneline --graph --all


Pull Requests (PR)

1. What is a Pull Request?

A Pull Request (PR) is a GitHub feature that allows developers to propose changes from one branch into another branch.

Other developers can review the code, discuss it, request modifications and approve it before merging.

Important: A Pull Request is a GitHub collaboration feature, not a Git terminal command.

2. Why do we use Pull Requests?

  1. To review code before merging.
  2. To discuss proposed changes.
  3. To find mistakes and bugs.
  4. To collaborate with team members.
  5. To maintain code quality.
  6. To keep track of development work.

. How to create a Pull Request

Suppose you have created a branch named login-page.

Step 1: Switch to the branch.


git switch login-page

Step 2: Make changes to your code.

Step 3: Stage your changes.


git add .

Step 4: Commit your changes.


git commit -m "Added login page"

Step 5: Push the branch to GitHub.


git push -u origin login-page

Step 6: Open your repository on GitHub.

Step 7: Select Compare & pull request, or open the Pull requests tab and select New pull request.

Step 8: Select the branches:

  • Base:

    main

  • Compare:

    login-page

Step 9: Add a title and description.

Step 10: Click Create pull request.

Step 11: Wait for the code review.

Step 12: Once approved, merge the Pull Request if you have permission.

4. What happens after merging a Pull Request?

The changes from the feature branch are incorporated into the target branch.

Example:


login-page  ── Pull Request ──>  main

The main branch now includes the approved login page changes.

5. Pull Request vs Merge

Pull Request Merge
Proposes changes for review Combines changes
Usually created on GitHub Can be performed locally using Git
Supports discussion and approval Does not itself provide a review process
Can be closed without merging Performs the integration


Fetch and Pull Commands

These two commands are very important when working with remote repositories.

. What is git fetch?

git fetch downloads new commits and references from a remote repository without automatically integrating those changes into your current branch.

In simple words:

It checks for updates from GitHub and downloads the information so you can inspect it before integrating it.

Command:


git fetch origin

After fetching, check the changes:


git log --oneline main..origin/main

This shows commits in origin/main that are not yet in your local main.

2. What is git pull?

git pull retrieves changes from a remote repository and integrates them into your current branch.

Comment:


git pull origin main

The exact integration behavior can depend on Git configuration. Commonly, Git fetches and then merges; it can also be configured to rebase.

3. Difference between fetch and pull

Git fetch Git pull
Downloads remote updates Downloads and integrates updates
Does not change your current branch's files by itself May change your current branch and working files
Allows you to inspect updates first Convenient for updating your branch
Useful before reviewing remote changes Useful when you are ready to integrate them

4. Example

Suppose your teammate has updated the CodePath homepage on GitHub.

You want to get those changes.

First, you can use:


git fetch origin

Then inspect the changes.

If you want to integrate the updates:


git merge origin/main

Or use:


git pull origin main

Remember:

  • Fetch = Download remote updates.
  • Pull = Fetch and integrate remote updates.


Resolving Merge Conflicts

1. What is a Merge Conflict?

A merge conflict happens when Git cannot automatically combine changes from different branches or commits.

This can happen when two developers edit the same part of a file differently.

Example:

Developer A changes the heading to:


<h1>Welcome to CodePath</h1>

Developer B changes the same heading to:


<h1>Learn Coding with CodePath</h1>

Git may not know which version should be kept.

This is called a merge conflict.

2. How to identify a merge conflict

Git may show something similar to:


<<<<<<< HEAD
<h1>Welcome to CodePath</h1>
=======
<h1>Learn Coding with CodePath</h1>
>>>>>>> login-page

Meaning:

  • <<<<<<< HEAD – Start of the current branch's version.
  • ======= – Separates the two versions.
  • >>>>>>> login-page – End of the incoming branch's version.

3. How to resolve a merge conflict

Step 1: Open the conflicted file in VS Code.

Step 2: Examine both versions.

Step 3: Decide which version you want to keep, or combine both versions.

For example, you decide to keep:


<h1>Learn Coding with CodePath</h1>

Step 4: Remove the conflict markers.

Step 5: Save the file.

Step 6: Stage the resolved file.


git add index.html

Step 7: Complete the merge.


git commit -m "Resolved merge conflict"

If you were resolving a merge that Git had paused, the commit completes that merge.

If you were resolving a conflict during a rebase, use:


git rebase --continue

4. How to avoid merge conflicts

  • Communicate with your teammates.
  • Use separate branches for different features.
  • Pull the latest changes regularly.
  • Avoid editing the same section of a file simultaneously
  • Keep commits small and focused.
  • Review changes before merging.


Undoing Changes in Git

Sometimes developers make mistakes and need to undo their changes.

Git provides different commands for different situations.

Important: Before undoing anything, check your current status and understand whether the work is staged, committed or already shared.

Case 1: Undo staged changes

Suppose you have used:


git add index.html

But now you do not want to include that file in the staging area.

Use:


git restore --staged index.html

This removes the file from staging but keeps your actual file changes.

To unstage all files:


git restore --staged .

Case 2: Undo unstaged changes

Suppose you have modified a file but have not staged it.

You want to discard those modifications and restore the file to its last committed version.

Use:


git restore index.html

Warning

This discards the unstaged changes in that file. Make sure you do not need them.

Case 3: Undo a commit

There are two common approaches.

Method A: git revert


git revert HEAD

This creates a new commit that reverses the changes introduced by the latest commit.

It is generally the safer option when the commit has already been shared with others.

Method B: git reset


git reset --soft HEAD~1

Moves the current branch back one commit while keeping the changes staged.

Another option:


git reset --mixed HEAD~1

Moves the branch back one commit and leaves the changes unstaged.

By default, git reset HEAD~1 is equivalent to the mixed reset.

Case 4: Delete the last commit and its changes


git reset --hard HEAD~1

This removes the last commit from the current branch and discards the associated tracked working-tree and staging changes.


Dangerous command

This can permanently discard work if you cannot recover it. Do not use it casually, especially on a shared branch.

Case 5: Undo multiple commits

Suppose you want to undo several recent commits.

You can use:


git reset --soft HEAD~3

This moves the branch back three commits and keeps the changes staged.

Or use:


git reset --hard HEAD~3

This discards those changes from the current branch and working tree.

For shared history, consider reverting the relevant commits instead.

6. Difference between reset, restore and revert

Command Purpose
git restore Restores file contents
git reset Moves the branch or changes staging state
git revert Creates a new commit that reverses an earlier commit

This distinction is particularly important for beginners.
